## Idear
做一个能翻译多种文件或直接收文本输入的 Skill，供 AI Coding IDE 使用。
支持格式: .txt, .pdf, .docx, .md, .epub 等。
支持超大文件: 1000-2000 页。
支持直接输出成pdf,docx,或md，超大文件拆分多个输出。
建立评估标准，全部翻译完成后，或超长文本或文件部分翻译完成后，根据评估标准进行翻译质量审查并评分，如果达不到要求需要根据建议修改翻译直到达标

## 📋 任意文档翻译 Skill - everything-claude-code 跨会话保存 PRD 上下文的完整命令序列

### 🔄 完整流程（含跨会话保存）

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Any File Translator Skill - 跨会话工作流                   │
│                                                                             │
│   Step 1: /prp-prd            →  创建 PRD                                    │
│   Step 2: /save-session       →  保存会话（跨会话保存 PRD 上下文）               │
│   Step 3: architect           →  架构设计                                     │
│   Step 4: /blueprint          →  多 PR 规划                                   │
│   Step 5: /save-session       →  保存会话（跨会话保存 blueprint 多 PR 规划）     │
│   Step 6: /prp-plan           →  为每个 PR 生成详细计划                         │
│   Step 7: /prp-implement      →  执行计划                                     │
│   Step 8: /prp-pr             →  创建 PR                                     │
│   Step 9: /code-review        →  代码审查                                     │
│   Step 10: /save-session      →  保存会话（保存规划上下文）                      │
│   Step 11: Merge              →  合并分支                                     │
│   resume session blueprint    →  恢复会话（blueprint 多 PR 规划）              │
│   Goback 6 until finish       →  重复直到所有模块完成                          │
│   Step 12: /e2e               →  E2E 测试                                    │
│   Step 13: /save-session      →  保存会话（保存完成状态）                       │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

---

### 📝 详细命令序列

#### 会话 1: 产品和架构阶段

```bash
# Step 1: 创建 PRD
/prp-prd

# 输入描述:
# 创建一个能翻译任意文档或文稿本的的 Skill，供 AI Coding IDE 使用。
# 支持格式: .txt, .pdf, .docx, .md, .epub 等
# 支持超大文件: 1000-2000 页
# 支持直接输出成pdf,docx,或md， 超大文件拆分分多个输出
# 建立评估标准，全部翻译完成后，或超长文本或文件部分翻译完成后，根据评估标准进行翻译质量审查并评分，如果达不到要求需要根据建议修改翻译直到达标

# 输出: .claude/PRPs/prd/any-file-translator.prd.md

# Step 2: 保存会话（跨会话保存 PRD 上下文）
/save-session any-file-translator-prd

# Step 3: 架构设计
architect

# 输出: docs/architecture-design.md, docs/long-document-detection.md

# Step 4: 多 PR 规划
/blueprint any-file-translator "build document translation skill with multi-format output"

# 输出: plans/any-file-translator-build-translation-skill.md

/save-session any-file-translator-blueprint

```
---

#### 会话 2: 实施阶段

```bash
# 恢复会话
/resume-session any-file-translator-prd

# 生成 prp plan 
/prp-plan .claude/PRPs/prd/any-file-translator.prd.md

# 输出: .claude/PRPs/plans/{plan-name}.plan.md

# 创建 feature 分支
git branch feat/{plan-name}
git checkout -b feat/{plan-name}

# 执行计划（创建 feature 分支）
/prp-implement .claude/PRPs/plans/{plan-name}.plan.md

# Coding for core infrastructure

# Step 8: 创建 PR
/prp-pr

# 输出: PR {pr number}

# Step 9: 代码审查
/code-review {pr number}

# 输出: 审查结果

# 保存会话（保存完成状态）
/save-session any-file-translator-{plan-name}-done

# 提交新生成的审查报告和会话文件
/prp-commit

# Step 10: 合并分支
gh pr merge 1 --squash

# 返回 develop 分支
git checkout develop
```

---

按步骤启动不同的新会话实施所有计划，直到完成

---

#### 会话 8: 验收阶段

```bash
# 恢复会话
/resume-session any-file-translator-prd

# Step 11: E2E 测试
/e2e

# 输出: E2E 测试报告

# Step 12: 保存会话（保存完成状态）
/save-session any-file-translator-complete
```
